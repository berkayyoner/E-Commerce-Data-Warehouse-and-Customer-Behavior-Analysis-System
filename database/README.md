# Database

Oracle Free runs in Docker with four accounts in the `FREEPDB1` database:

| Account | Purpose |
|---|---|
| `dwh_oltp` | Shop data in the TPC-C layout, generated by BenchBase |
| `dwh_olap` | Data warehouse (star schema), filled by the ETL and segmentation services |
| `dwh_app` | Application tables (users and roles) of the auth service |
| `dwh_reader` | Read-only account of the report API: select on the warehouse and the OLTP tables |

## Folder layout

| Folder | Content |
|---|---|
| `init/` | Scripts that Oracle runs once when the container is created (creates `dwh_olap`) |
| `benchbase/` | BenchBase TPC-C configuration template |
| `enrichment/` | SQL that turns the benchmark data into e-commerce data |
| `migrations/` | Versioned Flyway scripts: `olap/` (star schema, ETL bookkeeping, segmentation, grants) and `app/` (users) |
| `scripts/` | Helper scripts |

## Generating the OLTP data

1. Copy `.env.example` to `.env` and choose the passwords.
2. Start the database: `docker compose up -d oracle-db`.
3. Build BenchBase with the Oracle profile (it needs Java 23, so a Maven container is the easiest way):

   ```bash
   git clone https://github.com/cmu-db/benchbase.git
   docker run --rm -v "$(pwd)/benchbase:/src" -w /src -e BENCHBASE_PROFILE=oracle maven:3.9-eclipse-temurin-23 mvn -B clean package -P oracle -DskipTests
   tar xzf benchbase/target/benchbase-oracle.tgz
   ```

4. Run the load script from PowerShell:

   ```powershell
   .\database\scripts\load-oltp.ps1 -BenchBaseHome C:\tools\benchbase-oracle -ScaleFactor 10
   ```

The script creates the TPC-C tables, loads them, runs a short transaction workload and then applies
`enrichment/01_enrich_oltp.sql`. With 10 warehouses the result is about 300,000 customers, 300,000+ orders
and 3 million order lines.

## What the enrichment adds

TPC-C has no product categories, real dates or repeat customers, which a warehouse needs. The enrichment adds:

- `ITEM.I_CATEGORY` and `ITEM.I_BRAND`
- `WAREHOUSE.W_REGION`, a Turkish city per warehouse and `CUSTOMER.C_REGION`, `CUSTOMER.C_EMAIL`
- order dates from 2024-01-01 to 2026-11-01 and `OORDER.O_PAYMENT_METHOD`
- delivery dates on order lines and payment dates in `HISTORY`
- a skewed customer choice per order, so a few customers buy often and most buy rarely

## Creating and changing the warehouse and application tables

The tables are created by Flyway migrations (`migrations/olap`, `migrations/app`). Flyway runs in a container, so
nothing has to be installed:

```powershell
.\database\scripts\migrate-database.ps1 -Schema olap
.\database\scripts\migrate-database.ps1 -Schema app
.\database\scripts\migrate-database.ps1 -Schema olap -Command info
```

A database that was created before Flyway was introduced already holds the objects of the first versions; mark them
as applied once with `-Command "baseline -baselineVersion=6"` (olap) or `-Command "baseline -baselineVersion=1"` (app).
A new migration is a new file with the next version number (`V8__description.sql`); it must grant `select` on every
table it creates to `dwh_reader`. Applied migrations are never edited. The schema is described in
`docs/star-schema.md`; backup and operations notes are in `docs/database-operations.md`.
